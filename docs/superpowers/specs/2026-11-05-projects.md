# Projects (2026-11-05)

The decided design for Projects. The clickable prototype is the Claude Design canvas "Trov Projects", saved as
`docs/superpowers/specs/2026-11-05-projects.dc.html` (one artboard; its `renderVals()` holds every state and its copy).
The contract is `shared/projects-core.ts` (DTOs, routes, limits, words) plus the project fields in
`shared/ai-ask-core.ts` (`AskRequest.projectId`, `AskThreadSummary.project`, `AskThreadPatch.project`). Where this
file and the prototype disagree, this file wins; where the code and this file disagree later, the code wins and
`docs/architecture/projects.md` says so.

## What a project is

A place to work on one piece of work. It **points at** team records and **owns** only what is made inside it.

- **Owns:** its details (name, description, icon, colour), its **instructions** (≤ 2000 characters), its members,
  its **threads** (`chat_threads.project_id`), and the **artifacts** saved from its threads or uploaded into it
  (`artifacts.project_id`).
- **Points at (pins):** tickets, sprints, docs, decisions, PRs, repos and artifacts, by Ask ref (`ticket:87`,
  `sprint:12`, `doc:deploys`, `pr:185`, `repo:SaplingLearn/sapling`, `artifact:<slug>`). A pin is live: it is drawn
  through Ask's `RefView` for the reader, so a ticket always shows its current status. A pin the reader can't see is
  `{ ref, hidden: true }` and is left out of their answers.
- A thread or an artifact is in **at most one** project. A thread moves in or out by `PATCH /ask/threads/:id
  { project }` (its owner only, into a project they can open). An artifact's `project_id` is set when it is saved
  from a project thread or uploaded on the project page.

## Who can do what

| | Owner | Editor | Viewer | Org admin (not owner or member) | Other member |
|---|---|---|---|---|---|
| Open, read instructions, pins, artifacts | ✓ | ✓ | ✓ | `org` projects only | `org` projects only |
| Start chats in it | ✓ | ✓ | ✓ | `org` projects only | `org` projects only |
| Edit details, instructions, pins, upload files | ✓ | ✓ | | | |
| Members and visibility | ✓ | members only | | | |
| Archive / restore | ✓ | ✓ | | ✓ | |
| Delete | ✓ | | | ✓ | |

- `private`: owner only; adding members is refused (`400 invalid`), and switching a project to private keeps the
  member rows but ignores them until it is switched back.
- Every route answers a project the person can't open with the ONE `404 { error: "not_found" }` (never 403 for a
  project they can't see; 403 `forbidden` only for a project they can open but not change).
- Threads keep Ask's own privacy: a project member sees **their own** threads in the project, plus threads others
  **shared** with them or with the org (Ask's sharing, unchanged). Being in a project never shares a thread.
- An archived project is read-only (writes answer `409 { error: "archived" }`), is left out of new answers, and
  doesn't count toward the `projects` limit.
- **Pinning something less visible than the project** (a private artifact in a `members` or `org` project) is refused
  with `400 { error: "private_pin" }`; the screen offers "Publish to org" first.

## Limits (shared/plans.ts)

Two new `LIMIT_KEYS`: `projects` (per org, live projects) and `project_pins` (per project). Free and Personal 2 and 20;
Pro null (unlimited) and 200; Enterprise null and null. Enforced with `requirePlan` (402 `plan_limit`, the app's one
body). Not per seat.

## Data (migration `0086_projects`)

- `projects` (`id`, `org_id`, `slug` UNIQUE per org, `name`, `description`, `icon`, `color`, `instructions`,
  `visibility` CHECK, `owner` handle NOCASE, `archived_at`, `archived_by`, `deleted_at` (slug stays reserved),
  `created_at`, `updated_at`).
- `project_members` (`org_id`, `project_id`, `handle` NOCASE, `role` CHECK editor/viewer, `added_by`, `added_at`;
  PK project + handle).
- `project_pins` (`id`, `org_id`, `project_id`, `ref`, `added_by`, `added_at`; UNIQUE project + ref).
- `chat_threads.project_id`, `artifacts.project_id` (nullable, indexed with `org_id`).
- Every handle column in `HANDLE_COLUMNS`; every table in `ORG_TABLES`, `scripts/seed/reset.mjs` and the dev seed.

## Deleting

Delete goes through `src/deletion/projects.ts` (invariant 11 names it): one batch removes the project's pins,
members and the project row is marked `deleted_at` (its slug reserved); its threads are deleted through Ask's
existing thread deletion (`src/deletion/ask.ts`), including threads others shared; its artifacts stay in the library
with `project_id` cleared. The confirm copy is the prototype's: "Its N chats are deleted, including any shared with
the project. Its N artifacts stay in Artifacts. The tickets, docs and PRs it pinned aren't touched."

## Ask in a project

- `POST /ask { projectId }` on a new thread puts it in the project (the person must be able to open it, and it must
  be live). A thread in a project whose project the person can no longer open behaves as a thread with no project.
- **Every turn in a project thread** adds to the prompt: the project's name, its instructions, and its pins as
  stored ref cards (the same card text Ask's tools return), within a budget (`ASK_PROJECT_CONTEXT_MAX` tokens,
  pick ~6000; past it, the newest pins first and a line saying how many were left out). The instructions are
  written by other people: they enter the prompt **fenced as untrusted data** exactly as the turn fences other
  stored content (`docs/architecture/ask.md` › Grounding, untrusted content) — they shape the answer, they never
  grant tools or override the system rules. Hidden pins never enter.
- The turn emits one `activity` step before the model is called: "Read the project's instructions" (icon `docs`,
  run → done at once), like the attachment notices. The search tools look in the project's pins first (a pinned
  result ranks first); no new tool is added.
- **Save as artifact** from a project thread sets `artifacts.project_id`.
- Archived project: its threads still open and read; a new question answers as a thread with no project context.
- Model calls stay where they are (invariant 14): nothing new calls a model.

## The screen

From the prototype, built on the app's real pieces:

- **Sidebar:** one new row, **Projects**, in Workspace after Trov (a folder icon). The DOM stays structurally stable
  (`test/render.sidebar.test.ts`). No badge.
- **Projects list** (`#projects`): header "Projects" with **New project** (accent); the page title and line; a search
  (`cnpy-sfbar`) with a Sort control; a `segmented()` All · Mine · Shared with me; the count line ("4 shown · 4
  total"); **Recent** (three Library-style cards) only with no search and All; then the list (Project, Who can see
  it, Owner, Chats, Pinned, Updated, ⋯), and "Archived · N" that opens the archived rows with Restore.
- **Project home** (`#project/<slug>`): the tile, name, description, the avatar stack and the visibility line; Share
  and the ⋯ menu (Edit details, Members and visibility, Archive, Delete project); the Ask composer, full width of the
  column below it, sending a new thread with `projectId`; `tabBar()` Chats · Artifacts with counts; the right column
  with Instructions (Edit in place, the counter, Save / Cancel) and Knowledge (pins grouped by type with their marks,
  remove on hover, Add, "N of 200 pinned", Upload files).
- **A chat in a project** is the Ask screen. The crumb reads "Projects › <project> › <thread>"; the thread list's
  first group is "In <project>" (the project's threads), then the person's usual groups; the composer shows the
  project chip and its foot line "Uses <project>'s instructions and N pinned items".
- **Thread menu**: a "Move to project" item with the person's live projects and "Remove from project".
- **Dialogs** (`confirmModal` structure, the New space dialog's fields): New project / Edit details (name, icon,
  colour, who can see it, short description; the plan line); Add to <project> (search, type switch, grouped
  candidates with their marks, already-pinned rows checked and disabled, the private-artifact warning with Publish
  to org, the upload drop zone, "N selected", Add N); Share (who can see it, add people, the member list with each
  role, the note); Delete (the copy above).
- **States:** empty project (the ghost lines and their copy), Free at the project cap (owner: Upgrade to Pro;
  member: "An owner can upgrade, or archive one"), a viewer (no Edit, no Add, no remove), a hidden pin ("An item you
  don't have access to"), archived (the line with Restore), loading (skeleton), a failed read ("Couldn't load this.
  Try again" in place).
- Toasts with Undo for Add to Knowledge and Archive.
