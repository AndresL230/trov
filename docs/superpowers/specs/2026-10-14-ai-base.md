# AI base: what this build delivers (2026-10-14)

Handoff #6. The full AI system (which events trigger what, batching, which model decides what) is **not
decided**; `2026-10-14-server-ai.md` is background only. This build delivers three things and nothing
that decides when the model runs or produces content for the new screens.

| PR | Branch | Delivers |
| --- | --- | --- |
| 1 | `ai/anthropic-summaries` | PR and issue summaries move from Gemini to Claude Haiku 5.5 behind a provider-agnostic client (`src/ai/client.ts`, `src/ai/schema.ts`). Same fields, prompts and storage; no migration. |
| 2 | `ai/base` (stacked on 1) | The `ai_runs` allowance, the org AI switch, an empty AI pass in the `*/10` tick, `ai_suggestions` / `ai_feedback` and their cookie routes, the typed screen contracts (`shared/ai.ts`, `shared/ai-core.ts`), optional fields on the existing reads, and `LOCAL_AI_PREVIEW` fixtures. As built (`docs/architecture/ai.md`): `ai_runs` is not listed on the pricing page / Plan block / Settings yet (`LimitDef.listed: false`); the pass runs on every tick with NO heavy job (never on `:00`'s usage polls or the 6-hourly progress / reconcile), after the health pings; `LOCAL_AI_PREVIEW` is honoured for a request to a loopback `http://` origin with no live Stripe key (its value is a mode, not a URL, so the request's own origin is what says `wrangler dev`); `get_repo_dashboard` carries `state` with overview and `themes` with planning when present; accept answers `not_found` → `not_open` → `not_available` → `forbidden` → `invalid` (a bad body). |
| 3 | `ai/screens` (stacked on 2) | The frontend: `web/src/ai-ui.ts`, Org settings › AI, Platform › Usage, and the four screens (My Work brief, Repo State, Feed AI entries, Where the work went), rendered only when their field is present. |

## Verified before building (2026-10-14)

- `@anthropic-ai/sdk` pinned at **0.133.0** (published 2026-10-09). Under the repo's workerd test pool
  (`compatibility_date = "2025-11-01"`, `nodejs_compat`), `new Anthropic({ apiKey, fetch, timeout,
  maxRetries: 0 })` sends `messages.create` through the injected `fetch` to
  `https://api.anthropic.com/v1/messages`, and `output_config.format = { type: "json_schema", schema }`
  is typed (`OutputConfig` / `JSONOutputFormat`) and sent. `Model` includes `claude-haiku-5-5`;
  `StopReason` includes `refusal` and `max_tokens`.
- zod **4.4.3**: `z.toJSONSchema` works on our schemas. It emits `$schema`, `maxLength`, `minItems`,
  `maxItems`, `minimum`, `maximum` and already sets `additionalProperties: false` on `z.object`;
  nullable values become `anyOf [..., {type:"null"}]`. `toClaudeSchema()` strips `$schema` as well.
- The spec's Part 0 line references all still match `main` at 957eab4.
