## Layout

- `shared/` — the ONLY shared layer (imported via the `@shared` alias by `src/` and `web/`):
  `contract.ts` (Zod ingest contract), `vocabulary.ts` (controlled vocab), `rows.ts` (one type per D1 table),
  `dashboard.ts` (the My Work DTO shared by the Worker and web), `people.ts` (the person-profile contract —
  zod-free: the caps, `avatarSrc`, the profile / directory / agent DTOs), `repo.ts` (the Repo dashboard DTO — zod-free,
  since the SPA imports `REPO_TABS` as a value), `hosting.ts` (the hosting-provider contract — zod-free: providers,
  parts, roles, connection methods, the `hx_<metric>` vocabulary, deploy states, the setup and dashboard DTOs; see
  `hosting-providers.md`), `hosting-status-core.ts` (THE hosting status function), the repo-setups cores — all
  zod-free, see `repo-apps.md` — `repo-apps-core.ts` (app kinds, roles, `RepoApp`), `repo-facts-core.ts` (`RepoFacts`,
  `narrowFacts`, `layoutInputOf`), `repo-layout-core.ts` (`RULES`, `decide`, `TABS`, `layoutOf`), `repo-scan-core.ts`
  (suggestions, seen signals, the Apps DTO), `repo-apps-setup-core.ts` (signals ↔ `github` part settings) and
  `usage-families-core.ts` (`hosting-providers.md`), `notifications.ts` (the digest DTOs), and the
  tickets pair-per-domain: `tickets.ts` / `sprints.ts` (zod rows, DTOs, payloads, `parseTicketLink`,
  `toSprintView`) over `tickets-core.ts` / `sprints-core.ts`. **The `*-core.ts` split is a rule**: anything
  the SPA imports as a VALUE (`canTransition` / `legalMoves` / `TICKET_STATUS_LABEL` / `isOpenStatus`,
  the status/urgency/domain tuples) lives in the zod-free core so the browser bundle never drags zod in;
  the zod module re-exports it, so the server still has one definition.
  `site-pages.ts` is the public site's ONE page list (`SITE_PAGES`: path, kind, title, description, Open Graph
  image) with the head tags and JSON-LD it implies and the assets binding's generated `_redirects` / `_headers` —
  read by the build, the Worker's sitemap and the reserved slugs (`web-ui.md` › The public pages, for crawlers).
  `mcp-tools-core.ts` (zod-free) is how the site groups and describes the MCP tools; `mcp-tools.generated.ts` is
  the tools THEMSELVES as a client sees them — GENERATED by the web build from `src/mcp-catalog.ts`, never edited
  (`test/mcp-catalog.test.ts` fails while it differs from the registration). `error-hints.ts` is the one table of
  what an error code means and what to do next (`web-ui.md` › Errors an agent can act on).
  `doc-outline.ts` (zod-free) is a doc's H2/H3 outline and the heading slug rule: the Worker builds each doc's
  outline for `GET /docs` from it, and the reader's heading ids use the same `slugifyHeading`
  (`feed-and-search.md` › The Docs screen's reads).
  `fonts.ts` names the self-hosted font files (`web/src/fonts/`, with their OFL licenses), their unicode ranges and
  the stable `/fonts/` copies the Worker's own pages load (`web-ui.md` › Fonts, contrast and focus).
