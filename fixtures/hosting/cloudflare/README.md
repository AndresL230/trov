- `deployments.json` — Workers Deployments API `GET https://api.cloudflare.com/client/v4/accounts/{account_id}/workers/scripts/{script_name}/deployments` (documented; needs Workers Scripts Read). "The first deployment in the list is the latest deployment actively serving traffic."
- `analytics.json` — GraphQL Analytics API `POST https://api.cloudflare.com/client/v4/graphql`, `workersInvocationsAdaptive` grouped by `datetimeHour` AND `status`, `sum { requests errors subrequests }` (repo setups, Phase G). The `12:00` rows are the inclusive `datetime_leq` end and are dropped; `11:00` has no row — a quiet hour, a true zero inside the covered window. Step 0 CONFIRMED against a live account (the `trov` Worker, 7 days) that `status` is the invocation OUTCOME (`success`, `clientDisconnected` seen live) and that `subrequests` is a sum field; the two other statuses here (`scriptThrewException`, `exceededResources`) are Cloudflare's documented outcome names, hand-placed — UNCONFIRMED live (none occurred in the step-0 week).
- `scheduled.json` — `workersInvocationsScheduled` for the script over the window: per-run rows with `cron`, `status`, `datetime` (step 0 CONFIRMED the dataset and those fields live: three crons, 1226 rows in 7 days, all `success`). Hand-shaped around those facts: the `exceededCpu` failure is UNCONFIRMED (no failed run was seen live), and so are the filter field names `datetime_geq` / `datetime_leq` on this dataset. The `12:00:01` run is past the window and is dropped.
- `runtime.json` — the completed day's quantiles: `workersInvocationsAdaptive` with `dimensions { date }` and `quantiles { cpuTimeP50 cpuTimeP99 wallTimeP50 }` (µs). Step 0 CONFIRMED the quantile fields and these magnitudes live (cpuTimeP50 2257, cpuTimeP99 55106, wallTimeP50 23491, grouped by status). UNCONFIRMED: one row per `date` when grouped by date alone, and the `datetime_lt` filter.
- `d1.json` — `d1AnalyticsAdaptiveGroups` (`sum { readQueries writeQueries rowsRead rowsWritten }`) and `d1StorageAdaptiveGroups` (`max { databaseSizeBytes }`) by `date`, one alias pair (`q0` / `s0`) per database. Step 0 CONFIRMED both datasets, the fields and these values live for the prod `trov` database (2026-10-14: readQueries 9672, writeQueries 3093, rowsRead 2354377, rowsWritten 13712; size 27545600 on 2026-10-15) with Account Analytics Read.
